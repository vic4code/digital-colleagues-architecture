1. A colleague who remembers to check不用你再提醒，他也記得查看

OUTLOOK · AN ILLUSTRATIVE WORKDAY / 示範情境

“Keep an eye on Outlook during working hours. Tell me when a customer email needs my attention.”「上班時間幫我留意 Outlook。客戶來信有需要我處理的事情，再提醒我。」

At the next check, the colleague reads a customer email asking for a reply today. It checks the related information and prepares a private reminder with the email link. If nothing needs attention, it stays quiet.下一次查看時，他讀到客戶要求今天回覆的郵件，就查相關資料，整理成附有原信連結的私人提醒。沒有需要你注意的事，就不打擾。

The proactive part: you do not have to say “check now” or “continue” at every step.主動性在這裡：你不用每一步都說「現在去看」「接著做」。

This example assumes configured Outlook access, a checking responsibility and a notification channel. It illustrates a workflow, not a built-in Outlook integration in every framework.情境假設已設定 Outlook 存取、查看責任與通知管道；不是每個框架都內建 Outlook 整合。

2. What makes this possible?這件事背後，要解決什麼？

  1. What starts the check?他怎麼知道該去看？

    A scheduled time arrives, or a configured mail event is received.排程時間到了，或收到已設定的新信事件。

  2. What deserves attention?他怎麼知道要不要管？

    Read the actual email and judge it against the responsibility you gave.先讀原信，再依你交代的責任判斷。

  3. What should happen next?需要處理時，他怎麼做？

    Use connected tools to look up context and prepare the useful output.透過工具查資料，整理需要的成果。

  4. Is the work finished?做一半或做完之後呢？

    Continue pending work, wait for a result, or finish and deliver when appropriate.沒做完就接續或等待；完成後依需要送出提醒。

These questions explain the scenario. Each framework implements its own paths; this is not a universal lifecycle or a set of project phases.這些問題用來解釋情境；各框架有自己的執行路徑，不是共用的固定 lifecycle，也不是專案 phase。

Reading guide & terminology閱讀方式與名詞解釋

Feature names describe what the project offers. Triggers explain when work becomes eligible; transport explains how the signal arrives.官方功能名稱說明提供什麼能力；trigger 說明何時可執行，transport 則說明訊號如何送達。

One framework can have several mechanisms; one mechanism can accept several triggers.一個框架可以有多種機制；同一機制也可能接受多種觸發。The tables retain project feature names. “Schedule”, “external event” and “completion” describe trigger conditions for comparison; they are not universal modes or project phases. A polling timer can detect an event, and a webhook can deliver a scheduled job.以下保留官方功能名稱；時間、事件、完成是比較用的觸發條件，不是自行定義的通用模式或 phase。Timer 可以檢查事件，webhook 也可以派送排程工作。

Trigger / 觸發條件
The occurrence that makes work eligible: a deadline, incoming event or completed task.讓工作具備執行條件的事情，例如到期、事件到來或前項工作完成。
Payload / 工作資料
The data attached to a trigger, such as an instruction, event text or script. It tells the receiver what to process.觸發時附帶的指令、事件內容或 script；它不是 timer。
Fire / 一次觸發紀錄
One occurrence of an automation. A consumer is the code that receives and handles that occurrence.某個自動化被觸發的一次紀錄；consumer 就是接收並處理紀錄的程式。
Polling / 定期查詢
Repeatedly ask whether new work exists. The checked work may originate from time or events.定期問有沒有新工作；被查到的工作本身可能來自時間或事件。
Webhook / HTTP 事件通知
Another service sends an HTTP request when something happens. The receiver may filter it before starting an agent.外部服務主動送 HTTP 通知；接收端可先過濾，再決定是否啟動 agent。
Admission / 執行准入
Runtime checks whether a run may start now, including capacity, busy state and target-session rules.Runtime 根據容量、忙碌狀態與目標對話規則，判斷現在能否開始。
Lease / 有期限的工作租約
A temporary claim on queued work. Renewing it keeps ownership; it does not create another reasoning turn.暫時取得某筆工作的執行權；續租維持權利，不會自動新增思考回合。
Revival / 接續等待中的對話
Resume a conversation after a result or event becomes available.結果或事件到來後，喚回等待中的對話繼續處理。
Cadence / 執行節奏
How often a recurring check runs. Adaptive pacing changes the next due time.週期檢查多久執行一次；自適應節奏會調整下一次時間。
Goal continuation / 目標續跑
After a turn, decide whether the assigned goal needs another turn within its limits.回合結束後，判斷交付目標是否仍需要在限制內繼續。

Everyday examples assume the necessary accounts, tools and instructions have been configured. Outlook is an example work source, not a built-in integration claim for every framework.情境假設帳號、工具及交辦內容已設定好。Outlook 是工作情境示例，不代表每個框架都內建 Outlook 整合。

    def is_due(self, now: Optional[float] = None) -> bool:
        """Cheap check: active, not mid-wakeup, and the clock has passed."""
        s = self._state
        return (
            s is not None and s.status == "active" and not s.awaiting_response
            and (now if now is not None else time.time()) >= s.next_due_at

    def fire_tick(self) -> Optional[str]:

def check_monitor(job: dict) -> MonitorOutcome:
    """Run the monitor source and decide whether the agent should run.

    On change (or first run) the new hash + snapshot are persisted BEFORE the agent runs — detection
    time is the state boundary, so a failed agent run doesn't re-alert on the same content forever.
    On failure nothing is persisted.
    """
    job_id = str(job.get("id") or "")
    ok, output = _run_monitor_source(job)
    if not ok:
        return MonitorOutcome(ok=False, error=output)

    new_hash = hash_monitor_output(output)
    raw_state = job.get("monitor_state")
    last_hash = raw_state.get("last_output_hash") if isinstance(raw_state, dict) else None

    if last_hash is not None and new_hash == last_hash:
        return MonitorOutcome(ok=True, changed=False)

    first_run = last_hash is None
    old_output = "" if first_run else _read_last_output(job_id)

    shown_output = output
    if len(shown_output) > MAX_OUTPUT_CHARS:
        shown_output = shown_output[:MAX_OUTPUT_CHARS] + "\n... [output truncated]"

    current = f"### Current output\n\n```\n{shown_output}\n```"
    if first_run:
        context_block = (
            "## Monitor Baseline (first run)\n\n"
            "This is the first observation of the monitored source — there is "
            "no previous output to diff against.\n\n" + current
        )
    else:
        diff = build_monitor_diff(old_output, output)
        context_block = (
            "## MONITOR CHANGE DETECTED\n\n"
            "The monitored source's output changed since the last run.\n\n"
            f"### Diff (previous → current)\n\n```diff\n{diff}\n```\n\n" + current
        )

    _persist_monitor_state(job_id, new_hash, output)
    return MonitorOutcome(ok=True, changed=True, first_run=first_run, context_block=context_block)
