HISTORICAL CASE · OPENCLAW

Inferred commitments：從一句話，留下之後的關心。

Retired · 已退役

使用者沒有要求提醒；系統從對話推斷「之後值得問一下」。下面是示意案例。

  1. 01 · Conversation
    「下週要跟供應商談續約。」
    Agent 回覆後，可能啟動背景抽取。
  2. 02 · Extraction + Store
    Follow-up candidate問問續約討論的進展due window · session · target
    高信心才保留，綁定原對話與收件對象。
  3. 03 · Heartbeat
    Due?未到期 ↺ 等待到期 → Check-in turn
    Heartbeat 檢查到期事項，開啟跟進回合。
  4. 04 · Check-in / Dismiss
    「續約討論還順利嗎？」
    送一次 check-in；或以 HEARTBEAT_OK 略過。
當時能做什麼？

主動問近況。到期回合不能使用工具，無法即時查證契約是否完成。

退役的是哪一段？

背景 extractor 與 commitment delivery 已移除。Heartbeat 仍可用，但不會自動承接舊抽取器。

為什麼收掉？

查到的移除紀錄未交代決策原因。不能據此推斷是成本、騷擾或效果問題。

Implementation limits · 當年的限制與原始證據

Opt-in，預設關閉。背景 extraction 使用隔離 context、無工具；不是每次回覆必跑。due 至少延後一個 heartbeat interval；maxPerDay 預設每個 agent session 的 rolling day 最多 3；到期不重播原始對話，target: none 不外送。

Task discovery ≠ Inferred follow-up · 原研究判準怎麼用？

Task discovery：依職責與現況產生未逐件交辦的新工作，可用 Scheduled observation turn 組合。Inferred follow-up：從對話自行抽取、持久保存，之後到期再跟進；是更窄的功能。

OpenClaw 移除的是舊 extractor／delivery 子系統；不是被 heartbeat 自動接替。已查退役資料未交代完整決策原因。自訂 heartbeat prompt 仍可組合角色選題，但不是恢復原機制。

05 / CATHAY SCENARIOS & EVIDENCE

Cathay scenarios，
看到什麼、想到什麼，怎樣算通過？

法務／法遵：定期到期清單 → 交辦補齊送審資料 → 自行發現值得檢視的契約並提案。

國泰情境假設，未接實際內部資料。唯讀來源、私有收件匣、人審；不對外寄送。

Metrics · 指標與分母
指標定義避免誤讀
Wake coverage有結果的到期 occurrence／應到期 occurrence分 timer、event、human、inbox-open；模型呼叫數不是主動次數
Proposal usefulness人工判定有用／已評閱提案未讀另列；只看採納無法知道漏判
Opportunity recall有提出的標註機會／全部標註機會需離線標註集或定期人工抽查，不能從線上提案自算
Unsupported / Duplicate rate不合格提案／所有生成提案保留投遞前被擋的提案，才有分母
注意力與成本標題已讀、內容開啟、接受／退回／延後；每次有效提案成本不把開過等同有用；含生成後被擋成本
可靠性來源延遲、各處理階段耗時、恢復時間、預算耗盡、cursor lag零模型不等於零資源成本；trace 是理由與證據，不存隱藏思考鏈
