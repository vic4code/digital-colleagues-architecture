Mechanism inventory audit — 2026-09-09

Scope: pinned repository source and same-commit project documentation. Trigger conditions are analytical labels, not new phases. Static source tracing, not live runtime verification. The inventory covers identified proactive entry and continuation paths; it does not claim exhaustive coverage of all extensions or deployment configurations.

openclaw/openclaw @ 91ea838947d30a65f1299b05fa42071917f2a293

  • Heartbeat — Schedule OR event wake. Monitor due → heartbeat admission → agent turn. /hooks/wake can enqueue context and request an immediate heartbeat; next-heartbeat queues context only. Code Project docs
  • Automations / cron — Saved time / interval / cron. For at / every / cron schedules: due job → payload dispatch. Payload selects heartbeat, system event, agent turn or script work. Event schedule variants are listed below. Code Project docs
  • Inbound webhooks · /hooks/agent — External HTTP event. Validated hook → session admission → isolated agent turn. This route can submit work directly without waiting for a recurring heartbeat. Code Project docs
  • Automations · on-exit — A watched command exits. Supervised command completes → watcher fire → shared cron execution admission → one-shot payload. Completion is the trigger, not a deadline. Code Project docs
  • Automations · stream — Lines arrive from a supervised command. stdout / stderr → match and bounded batch → fireBatch → cron.run with stream context. Batch timing coalesces events; it does not create them. Code Project docs
  • Automations · condition watchers — A scheduled check or stream batch passes a condition. Headless trigger script reads input / saved state → fire:false skips payload; fire:true dispatches it. No model needed to evaluate the script itself. Code Project docs
  • next_check · adaptive pacing — A supported scheduled run finishes. Run-scoped delay request → success / bounds checks → persist next due time. This modifies a schedule; it does not create a separate event source. Code
  • Skill Workshop · experience review — Eligible work ends + idle delay. Eligibility → delayed background review → permitted workshop changes. Distinct from checking external work. Code Project docs
  • Dreaming · memory maintenance — Managed scheduled job. Managed cron → memory consolidation / promotion / diary. Memory maintenance is not evidence of new external goal discovery. Code Project docs
  • Goals · evidence boundary — Explicit goal setup / update. Goal state and controls exist. A universal post-final automatic continuation producer was not established in this audit. Code

NousResearch/hermes-agent @ fef0e16fe19b79ded929209f87c7434270b03825

  • Cron / cronjob — Saved deadline or recurring schedule. tick → claim due job → run_one_job → fresh agent session → delivery / next schedule. no_agent takes a script-only branch. Code Project docs
  • Webhooks — External HTTP event. Authenticate → event / payload filters → optional script → prompt → MessageEvent → handle_message. deliver_only bypasses the agent. Code Project docs
  • Session heartbeat · /heartbeat — Recurring instruction becomes due. Watcher checks session / user queue → admitted normal conversation turn. Recurrence does not itself define a new goal. Code Project docs
  • Loop · /loop, /proactive — Timer tick; fixed or self-paced. fire_tick → repeated turn → marker / optional judge / caps → stop or next tick. Separate from persistent-goal continuation. Code Project docs
  • Persistent Goals · /goal — Eligible turn finishes; goal remains active. Post-turn hook → gates + judge + budget → continue / wait / pause / done. Continuation enters the session queue. Code Project docs
  • Kanban dispatcher — Task becomes ready; dependencies complete. Periodic board sweep → promote / claim → spawn assigned worker. State makes work eligible; polling discovers that state. Code Project docs
  • Background review — Eligible turn finalization. Finalizer → background review → restricted improvement writes. This is maintenance after work, not a new external assignment. Code
  • Cron provider · Chronos — Remote schedule fires via HTTP. Authenticated /api/cron/fire → provider claim → shared run_one_job. Logically time-based, although its transport is a webhook. Code Project docs

CopilotKit/OpenBot @ 7b94a0b802732e6491634160cf9ed3fcfb813424

  • Routines — Saved routine becomes due. Worker sweep → durable work item → lease → current owner/access checks → channel turn → next occurrence. Code Project docs
  • Bot handoff · message_bot — An agent delegates work. Typed task + trusted identity / grants → durable hop → claimed delivery → recipient Bot turn. Assigned work, not self-created goals. Code Project docs
  • Handoff result relay — A delegated turn produces an answer. Successful forward hop with answer → queued relay → follow-up delivery. answerIn prevents relay-of-relay recursion. Code Project docs
  • Lease heartbeat · not an agent wake — A claimed run is still executing. Renew queue / thread ownership while work runs. No new task or model turn is created by the lease renewal itself. Code

b-nnett/grok-bot-0.18-reconstructed @ a9f633e09d49a85829b8236331b9e21f7e612634

  • Automation fire consumer — Cloud fire arrives; consumer polls. Poll transport → validate / acknowledge fire → guarded automation run. Upstream scheduling semantics are not proven by this local consumer. Code
  • Background event wakes — Subscribed / routed event. Event collected → background queue → transcript run. This is event follow-up in reconstructed host code. Code
  • Completion revivals — Background subagent finishes. Completion → ownership / duplicate checks → revive or drain waiting transcript → follow-up run. Code
  • Goal continuation handler · partial evidence — Continuation action is supplied. Validate action / goal identity → anti-spin guard → simulated user continuation. The automatic producer of that action remains unverified. Code

MineDojo/Voyager @ 55e45a880755d0c8c66ca7fb5fe7962ac8974f89

  • Automatic curriculum — A rollout ends inside learn(). Update progress → propose next task from state / history → next rollout, until iteration limit. This selects tasks within the assigned exploration domain. Code
  • Iterative prompting + self-verification — Execution feedback / failed attempt. Environment feedback + critic → revise code / retry within rollout bounds. Retry of a task and selection of a new task are different stages. Code

Distinctions established in this audit

  • OpenClaw inbound HTTP hooks are separate from internal event hooks and outbound webhook delivery. /hooks/wake queues an event and optionally requests a heartbeat; /hooks/agent submits an isolated turn directly.
  • Hermes ordinary webhooks can trigger an agent or use deliver_only. Its remote cron fire endpoint receives a scheduled occurrence over HTTP; transport and logical trigger differ.
  • Hermes Kanban dispatch is readiness-driven work detected by a periodic sweep, not a mandate to create a new task each minute. Kanban acceptance/review internals were not fully audited here.
  • OpenBot handoff result relay is part of the handoff lifecycle, not an unrelated independent scheduler. Queue lease renewal does not create reasoning turns.
  • Grok cloud fire polling proves the consumer path, not proprietary upstream scheduler semantics.
  • No claim of generic human-like curiosity follows from timer/event support alone.
